# Lab 2 Reflection (MAPLE M3)

AI's role was integral to the implementation of our Lab 2 prototype. It became a workflow partner across architecture, debugging, and documentation. One concrete example was frontend-backend integration. After we connected Angular to the Node/Express API, we encountered multiple environment and runtime issues (for example, the UI calling `m3.maristchat.com` during local testing and browser DNS failures). AI helped us quickly trace the issue to environment configuration and build behavior, then validate the local API path setup. Another example was the asynchronous UI rendering bug where assistant responses only appeared after a user click. AI-guided debugging helped us identify this as a change-detection/runtime behavior issue, and we implemented a fix so responses render immediately after async completion. We also used AI to improve API response handling and test flow reliability, including surfacing structured error handling patterns for 422/502 responses and distinguishing expected retrieval failures from actual system faults.

The biggest technical challenge was retrieval reliability under real data conditions. Our design doc baseline assumed a `0.70` similarity threshold, but during live testing with ingested Admin Directory data, valid queries (for example, Registrar office lookups) produced `RETRIEVAL_FAILED` despite the data existing in `Documents` and `DocumentEmbeddings`. AI support helped us troubleshoot this systematically: verify ingestion counts, inspect retrieval metadata (`chunks_retrieved`, `top_score`, threshold applied), and isolate that this was a threshold/precision-recall issue rather than a data absence issue. We tuned threshold behavior to `0.55` for the current implementation to reduce false negatives and documented the tradeoff (better recall, potentially noisier sources). Another challenge was backend consistency: the status route originally referenced a non-existent `CampusEvents` table. With AI-assisted review, we refactored that route to use the existing `Documents` source model (`source_type = 'Events'`) so the endpoint matched the actual schema.

Several implementation details changed from the original design doc, and we documented each deviation with rationale to ensure transparency:

* DGX Spark Migration: The most significant architectural deviation was shifting our AI generation and embedding pipeline entirely to local models via the campus NVIDIA DGX Spark. To eliminate cloud API costs, we replaced cloud-hosted frontier models with Ollama, utilizing nomic-embed-text for embeddings. This required updating our pgvector schema from 1536 to 768 dimensions.

* Data Ingestion Refactoring: While the design doc specified Playwright for all scraping, timeout issues on static pages (like the club directory) prompted us to refactor our scripts to use Cheerio, resulting in faster and more reliable execution.

* Narrowed Ingestion Scope: For MVP safety in Lab 2, /api/v1/campus/ingest currently supports Admin ingestion only via API trigger, while broader domain ingestion is still script-driven.

* Retrieval Threshold Calibration: The threshold moved from the design baseline (0.70) to an active calibration (0.55) based on observed false negatives in administrative queries.

* Expanded Query Routing: We added explicit administrative intent keywords (e.g., registrar, office, directory) to improve domain filtering for office-navigation questions.

* Frontend Runtime Behavior: We adjusted asynchronous UI rendering to ensure assistant responses render immediately after async completion, improving usability and reducing confusion during demos.

AI had a great impact on our team’s collaboration and productivity because it allowed us to develop extremely quickly, which gave us more time to meet and go over our findings. Instead of spending entire sessions blocked on one bug, we used AI to accelerate root-cause analysis, test hypotheses, and compare implementation options. That shift improved how we worked as a team: meetings became less about firefighting and more about validating decisions, reviewing tradeoffs, and aligning our implementation with MAPLE architecture and Lab 2 requirements. AI also improved our documentation process by helping us keep README/design-doc updates synchronized with real code changes, which is important for rubric alignment and final-project continuity. Overall, AI increased both delivery speed and quality of team communication.
